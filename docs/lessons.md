### `grep --exclude` silently no-ops on `.md` files in this repository

- **Source:** Discovered 2026-09-04 while writing a worktree-migration prompt whose history-preservation guard relied on `--exclude` to keep `docs/changelog.md` from being rewritten.
- **Problem:** A repo-wide sweep written as `grep -rln PATTERN --exclude=changelog.md .` still reports `docs/changelog.md`. Every `--exclude` naming a `.md` file is ignored — no warning, no error, no non-zero exit. A guard built on it fails open, and a verification step built on it can never come back clean.
- **Lesson:** Claude Code replaces `grep` with a shell function that runs ugrep with `--ignore-files`, which honors `.gitignore`. This repository's `.gitignore` ends with the negation `!**/*.md`, and ugrep turns a gitignore negation into a forced include that overrides `--exclude`. Verified 2026-09-04 against ugrep 7.8.4; the identical command under `command grep` (GNU grep 3.11) excludes correctly. It still works when the search root is a subdirectory such as `docs/`, because the negation is only loaded from a `.gitignore` at the search root.
- **Standing instruction:** Never rely on `grep --exclude` to omit a `.md` file in this repository. Filter the output instead — `grep -rn PATTERN . | grep -vE '(^|/)(changelog|future-todos|lessons)\.md:'` — which no ignore-file glob can override. Reach for `command grep` when you specifically need GNU grep semantics.

### A restart guard must not short-circuit the initialization its consumers depend on, and it must be consumed

- **Source:** 2026-09-06 self-update fix (branch `worktree-self-update-restart`; the plan file is local to the author's machine). Owner report: after `system-setup.sh` self-updated and restarted, no module update check ran until a second run.
- **Problem:** `check_for_updates` tested its restart guard before `detect_download_cmd`. The exec'd process sources the library fresh, so `DOWNLOAD_CMD` was `""`; every orchestrator and downloader gates `update_modules` on `[[ -n "$DOWNLOAD_CMD" ]]`, so the restarted run silently skipped module updates. Identical in all five libraries; `github/gh_org_*.sh` were already detect-first. The guard was also never consumed, so it stayed exported for every child of the restarted run.
- **Lesson:** An early-return guard placed before a side-effecting initializer starves every downstream consumer of that side effect on the guarded path: run the initialization before the guard can return, and state the contract ("populated on every return path where a tool exists") in the function's comment so the next parity copy inherits it. A process-restart marker is one-shot state — read it into a local and `unset` it ahead of *every* return path, or a child (including a long-lived server that seeds other shells) inherits a stale instruction.
- **Standing instruction:** Any new guarded entry point that also initializes a global its callers read MUST run that initialization before the guard returns, and any exported restart marker MUST be consumed with `unset` ahead of every return path. The `check_for_updates`-specific rules live in AGENTS.md §check_for_updates Pattern; `tests/test-self-update.sh` pins them.

### Launched scripts are `100755` in the index; only sourced libraries stay `100644`

- **Source:** Code review of the self-update restart fix, 2026-09-06 (`docs/backlog.md` entry "`check_for_updates` exec-restarts callers that are not executable in git"); closed 2026-09-07 by flipping 18 files.
- **Problem:** 18 tracked launchers — the three `_download-*-scripts.sh`, the three `github/gh_org_*.sh`, `lxc/{setup,start,stop,restart}-lxc.sh`, `kubernetes/{start,stop}-k8s.sh`, `llm/{ollama-remote,ollama-screen}.sh`, `system-setup/{install-desktop,pkgs-helper}.sh`, `utils/{disable-kvm-module,monitor-battery}.sh` — were `100644` in the index. Hosts that install through an accepted update never noticed (the install step sets the mode), but on a clone `./script.sh` failed with `Permission denied` (126), and an accepted `utils-*.sh`-only update set `any_updated=true` and then died at `exec "$caller_abs"` with the same 126 *after* the library had been replaced, so `update_modules` and `cleanup_obsolete_scripts` never ran. `tests/test-self-update.sh` could not see it: its accept path installs the downloaded temp, whose mode the install step sets.
- **Lesson:** The mode a file needs is decided by how it is invoked, not by its content. A file run as a program (`./x.sh`, `sudo ./x.sh`, `exec`) must be `100755`; a file that is only `source`d — the five `utils-*.sh` libraries, which `check_for_updates` installs at 644 on purpose — stays `100644`, as does `github/gh_org_copy-backup.sh`, a retained Legacy backup rather than a launcher. `tests/test-self-update.sh` pins the whole index in the allowlist form (every tracked `*.sh` is `100755`, and those six are `100644`), so the record of what is deliberately not executable lives in the test and a new sourced library has to be added there explicitly. Decision record: two run-time alternatives were considered and rejected — a defensive `chmod +x "$caller_abs"` before the `exec` (the backlog entry's own suggestion) and `exec "$BASH" "$caller_abs" "$@"` (proposed in the private repository's review of its variant). Both fix only the restart, leave `./script.sh` broken for the same users, and would paper over a wrong commit that the index assertion now catches outright.
- **Standing instruction:** Commit new launchers at `100755` (`git update-index --chmod=+x <file>` when the working tree was created without the bit). Do NOT add a run-time `chmod +x` or `exec "$BASH"` to `check_for_updates` without new rationale. Extend the allowlist in `tests/test-self-update.sh` only for a file that is sourced, with the reason beside it.

### macOS system scope is not root: never gate privileged work on `$EUID` alone

- **Source:** Review of the shell history-control change, 2026-09-11 (`docs/backlog.md` entry "macOS system scope leaves other users' dotfiles owned by the invoking admin", closed the same day).
- **Problem:** `configure_shell_for_user` and `configure_shell_prompt_colors_user` restored a dotfile's ownership only `if [[ $EUID -eq 0 ]]`, with `chown "$username:$username"`. On Linux, system scope runs as root and every user has a same-named group, so it worked. On macOS, system scope is a non-root admin elevating per command through `run_elevated`, so the gate never fired; had it fired, the chown would have failed anyway, because a macOS user's primary group is `staff`. The `mktemp` + `mv` replace path in `update_config_line` had the same shape: rename keeps the temp's owner, so a replaced line left the target owned by whoever ran the script, for other users' dotfiles and for `/etc/zshrc` alike.
- **Lesson:** "We are privileged" is `needs_elevation "$file"` (act through `run_elevated`) or `$EUID -eq 0` (act directly), never `$EUID` alone; and the owner to restore is a numeric `uid:gid` read from the file, or from its home directory for a dotfile that did not exist yet, with `get_file_owner`, never a name pair. `mv` over a file replaces its owner and mode with the temp's, so every `mktemp` + `mv` rewrite must restore both. `sed -i` needs no restore. Verified via https://raw.githubusercontent.com/apple-oss-distributions/text_cmds/main/sed/main.c: in-place editing runs `fchown(fileno(outfile), sb.st_uid, sb.st_gid)` and `fchmod(fileno(outfile), sb.st_mode & ALLPERMS)` unconditionally. Verified via https://cgit.git.savannah.gnu.org/cgit/sed.git/plain/sed/execute.c: `open_next_file()` runs `fchown (output_fd, input->st.st_uid, input->st.st_gid)` with a GID-only fallback. Decision record: an explicit chown after each `sed -i` was rejected as a guard for a case that cannot occur.
- **Standing instruction:** Gate ownership and other privileged fixes on `needs_elevation` / `$EUID -eq 0` as above, restore owners with `get_file_owner`, and do NOT add an ownership restore after a `sed -i` without new rationale. `kubernetes/utils-k8s.sh` keeps its own `update_config_line` and `backup_file` unchanged on purpose: neither is a roster helper, and that suite runs only as root on Linux, where the gap cannot open.
