### Added

- **`tests/`** — repo-wide tests. `tests/test-self-update.sh` covers `check_for_updates` in all five libraries (restarted, up-to-date, accepted caller update, accepted library update, declined update, nested caller, caller outside the library directory, HTTP 429, unwritable directories), pins the five bodies to a single digest, and also covers both orchestrators' flag handling and missing-module guard, the three downloaders' cleanup-then-exit-status contract, and the github standalones' guard spelling. Sandboxed with a recording `curl` shim: no network, no root, no writes to the repository.
- **`docs/backlog.md`** — work deferred from plans and reviews, with the entry schema stated in the file itself. Opened with two entries: the execution-guard form contradicting AGENTS.md §Important Implementation Notes #1, and `check_for_updates` exec-restarting callers that git records as non-executable. `docs/future-todos.md` keeps concrete feature gaps.

### Changed

- **`check_for_updates` is a byte-identical parity copy across the five libraries.** The five suite-specific guard names (`SYS_SCRIPTS_UPDATED`, `K8S_SCRIPTS_UPDATED`, `LXC_SCRIPTS_UPDATED`, `LLM_SCRIPTS_UPDATED`, `UTILS_SCRIPTS_UPDATED`) are retired in favour of one shared `SELF_UPDATE_RESTARTED`, which follows the prefixed convention every other restart guard in these repositories already used; nothing outside the libraries read the old names. A single checksum assertion now audits all five; the function joins the AGENTS.md roster, and `private`'s `utils-tmux.sh` is recorded there as a deliberate variant. One-time transition: a host whose old library restarts under a retired name sees the new library repeat the self-check once (two extra fetches, both `is up-to-date`; a caller update declined before the restart is offered once more) before the module updates run — no loop, because a second restart runs under `SELF_UPDATE_RESTARTED`, which the new library consumes.
- **`kubernetes-setup.sh` parses `--help`, `--skip-update`, and `--debug` like `system-setup.sh`.** `--debug` no longer has to be the first argument, and an unrecognised argument is now rejected with `✖ Unknown option` and exit 1 instead of being silently ignored.
- **Both orchestrators parse their arguments before sweeping stale temp files.** `--help` and a rejected option answer immediately; previously the sweep could stop for a "press any key to delete and continue" confirmation first.
- **The github standalones' restart guard is `SELF_UPDATE_RESTARTED`** (was camelCase `scriptUpdated`) — the same literal the five libraries share, so every self-updater in the repository now names its restart marker identically. It is compared as a string rather than with an arithmetic `-eq` test, which evaluates its operands as an expression. Sharing one name is safe because every holder consumes it unconditionally before any child can run.
- **AGENTS.md** §Orchestrator Pattern and §Complete Download Script Template show the real `check_for_updates` + `DOWNLOAD_CMD`-gate shape instead of `self_update`/`scriptUpdated`/a caller-side `REMOTE_BASE`; §check_for_updates Pattern codifies consume-the-guard-first, detection before the guard returns, and the guarded `mktemp` sites; §Key Directories and §README Locations gain the `tests/` rows and the missing `docs/` rows.
- **`system-setup/README.md`** now describes the line-1 shebang gate and the restart-then-continue flow accurately, and §Skipping Self-Update points at `--skip-update` instead of uninstalling curl/wget.

### Removed

- **BREAKING: `kubernetes-setup.sh` no longer reads the `SKIP_UPDATE` environment variable.** Use the `--skip-update` flag instead.

### Fixed

- **A self-update restart no longer skips the module update check.** `check_for_updates` tested its restart guard before `detect_download_cmd`. The exec'd process sources the library fresh with `DOWNLOAD_CMD=""`, the guard returned first, and `system-setup.sh`, `kubernetes-setup.sh`, and the three `_download-*-scripts.sh` — all of which gate `update_modules` on `[[ -n "$DOWNLOAD_CMD" ]]` — silently skipped every module update and the obsolete-script cleanup until a second run. All five libraries (`utils-sys.sh`, `utils-k8s.sh`, `utils-lxc.sh`, `utils-llm.sh`, `utils-misc.sh`) now detect the download tool before the guard can return; `github/gh_org_*.sh` already detected before testing their guard. Pinned by the new `tests/test-self-update.sh`, including the exec path.
- **Restart guards are one-shot.** The exported guard used to stay in the restarted process's environment for the whole run, so every child inherited it. `check_for_updates` now reads it into a local and `unset`s it ahead of every return path — including the one taken on a host with neither curl nor wget — and the three github standalones `unset` it after their update block.
- **`check_for_updates` can no longer abort the tool it is updating.** Both `mktemp` calls were bare assignments: under `set -euo pipefail` a failure (read-only or root-owned suite directory) killed the run at start-up, at the one point the function documents itself as never returning non-zero. Each site now reports the directory it cannot write and skips that half of the check; a library update accepted before the caller's temp fails still restarts.
- **A caller outside its library's directory no longer fetches an absolute URL on every run.** `caller_relpath` is derived by stripping `_UTILS_DIR`; a caller elsewhere kept an absolute path, so every run requested `<remote base>//home/... ` and reported an HTTP 404. That half of the check is now reported and skipped.
- **A module that never downloaded is named instead of crashing the run.** `update_modules` skips past a failed download before its create-if-missing step, so on a fresh install the orchestrator reached an unguarded `source` and died with bash's raw `No such file or directory`. Both orchestrators now verify every `system-modules/` (respectively `kubernetes-modules/`) entry of `get_script_list` exists and stop with a typed error listing what is missing.
- **`kubernetes-setup.sh` no longer aborts the whole setup when one module download fails.** `update_modules` returns 1 to report a partial failure it has already printed; called bare under `set -e` that ended the run. It now matches `system-setup.sh` (`|| true`).
- **`_download-lxc-scripts.sh`, `_download-ollama-scripts.sh`, `_download-utils-scripts.sh` run the obsolete-script cleanup after a partial failure and exit 1.** Previously `set -e` aborted before `cleanup_obsolete_scripts`.

## [2026-08-07]

### Fixed

- **The generated `rsyncd.conf` used `gid = root`, which does not exist on macOS — every macOS target daemon refused the transfer.** macOS has no group named `root`; gid 0 is `wheel`. Steps 1 and 2 both completed normally and the failure surfaced only in step 3, on the *source* host, as `@ERROR <module>: gid 'root' invalid` — the daemon resolves the module's user and group when a client attaches, not when the config is parsed, so the error pointed at the wrong machine and read like a tunnel fault. `uid` and `gid` are now numeric `0`, the superuser id on both platforms, which needs no name lookup at all. Both daemons accept a number: `rsyncd.conf(5)` documents `uid` as "the user name or user ID" and `gid` as "group names/IDs", and openrsync's `daemon_chuser_resolve_name` tries `getpwnam`/`getgrnam` first and falls back to `strtoll`. Found by the first real macOS ↔ macOS run; now pinned by four assertions, two of which reject a name-valued `uid`/`gid` outright.

## [2026-08-06]

Post-implementation review of the 2026-08-05 work. Findings are numbered F1–F33
in the review appendix of the originating plan.

### Added

- **`compose_transfer_args` and `validate_options` in `utils/rsync-over-tunnel.sh`.** Both are pure decision functions split out of `cmd_source_transfer` and `main()` for the same reason `build_daemon_config` was split out of `cmd_target_tunnel`: the flags a **root-privileged** rsync runs with, and the validation of every operator value that reaches a config file or a URL, are now assertable with no daemon, no sudo, no network and no second host.
- **`utils/tests/test-rsync-over-tunnel.sh` grew from 56 to 139 assertions**, covering the two new seams plus `_sanitize_ansi`, `print_warning_box`'s column alignment, `cmd_source_tunnel`'s ssh option-injection guard, the chroot ↔ `munge symlinks` pairing, `cmd_target_tunnel`'s refusal to write over an existing `--conf` or lock file, and `download_script`'s content gate (an HTML page quoting a shebang below line 1, a CRLF-terminated shebang, an empty body, and each HTTP-error arm — every rejection also deleting the downloaded file). It also gained an EXIT trap, so a `set -e` abort no longer leaks the `mktemp -d` directories it creates.

### Changed

- **bash 5+ is now the stated baseline for `utils/`, asserted once in `utils/utils-misc.sh`.** The per-script `BASH_VERSINFO` guard in `rsync-over-tunnel.sh` is gone; every script that sources the library inherits the check, which exits 69 with the remedy. The `docs/future-todos.md` item proposing a POSIX rewrite of `prompt_yes_no`'s `${default,,}` is dropped — bash-3.2 compatibility is no longer a goal, so there is nothing to work around.
- **Starting the daemon without chroot confinement now requires explicit consent.** On macOS with a non-Apple rsync, `use chroot = no` was previously applied after a three-line warning. It now shows what is actually lost — symlinks in the destination are unconfined, munging is deliberately off, and the module is unauthenticated, so any local user can write as root — and asks, defaulting to **no**. Non-interactive runs abort. This matches how the ACL/xattr degradation has always been handled, and that one costs fidelity where this one costs confinement.
- **`munge symlinks = no` is emitted only when chroot is off.** rsyncd already defaults munging off inside a chroot, so the directive was a no-op there and only gave openrsync's parser one more key to reject. Where it *does* apply it stays `no`, because munging rewrites every received symlink to `/rsyncd-munged/…` — corruption, for a tool whose payload is a container rootfs. The trade is now stated at the directive and enforced by a test.
- **Every canonical `print_*` helper writes with `printf '%b…%s'` instead of `echo -e`.** `echo -e` expanded backslash escapes in the *message*, so command output containing a literal `\033[2J` became real terminal control bytes — reintroducing the exact injection class `_sanitize_ansi` exists to close. `%b` still renders the colour constants (which are literal `\033…` in most copies), while `%s` keeps caller text literal, so one body works in every copy. Applied to all 11 parity copies across both repositories.

### Fixed

- **`--conf` pointed at an existing file destroyed it (data loss).** The generated daemon config was written with no existence check and no backup, and the EXIT trap then `rm -f`'d both it and a `.lock` path derived from it. `target-tunnel --conf /etc/rsyncd.conf` therefore clobbered and then deleted the host's real daemon config plus `/etc/rsyncd.lock` — a path the operator never named. Both paths are now refused with exit 73 if they already exist, which also makes the trap provably safe: everything it removes was created by that run.
- **`_sanitize_ansi` passed through every non-CSI, non-OSC escape sequence.** Both expressions anchored on `ESC [` and `ESC ]`, so `\ec` (RIS — resets and clears the entire terminal), `\e7`/`\e8` (save/restore cursor), `\eM` (scroll), ST-terminated OSC, and the DCS/SOS/PM/APC string types all survived. On a host where stdout is a TTY but `less` is absent, that content went straight to the terminal above a default-**yes** overwrite prompt. Rewritten with six ordered expressions covering all of them while still preserving SGR colour, applied to all 11 copies, and pinned by 16 assertions.
- **`print_warning_box` padded by bytes, not characters.** `printf "%-Ns"` counts bytes, so any row containing `•`, `—` or `✓` rendered short of the border — measured at 89 columns against a 91-column border. Rows are now padded on character count and over-long rows truncated on a character boundary. Three of the six copies also lacked truncation entirely and two carried a different body; all six are now byte-identical.
- **`show_diff_box` had drifted between the two repositories**, and its bottom border was one column narrower than its top. All 11 copies are now byte-identical, and the misplaced doc comment that sat above `_sanitize_ansi` instead of `show_diff_box` — still claiming `--color=always` is unconditional — is corrected and moved.
- **`check_for_updates` returned 1 when installing an update failed, killing the caller.** The message said "keeping local version" while `set -euo pipefail` at the bare call site exited the shell immediately. It now reports and continues, as the message always claimed. Same class fixed at the `self_update` and `update_modules` call sites, which document themselves as non-fatal and were also called bare.
- **`require_rsync` fed the output of a *failed* `rsync --version` to the capability parsers**, fabricating a capability profile that decides which flags a root-privileged rsync runs with. It now fails with exit 69.
- **`parse_rsync_protocol` and `parse_rsyncd_greeting` left the previous call's value in place on a failed parse**, so an unreadable `--version` silently inherited an unrelated build's protocol number — contradicting `require_rsync`'s own comment. Both now clear their output global first.
- **A stale `utils-misc.sh` made `rsync-over-tunnel.sh` die at file scope** with `detect_os: command not found`, before `main()` could offer the update that would repair it. It now fails with an actionable message naming the file and the fix.
- **The `lxc` → `xfer` module rename is documented where it can be seen.** The name is on the wire and both hosts must match, but only the changelog and a commit trailer carried it; `--help` and `utils/README.md` now state it, with the `--module lxc` escape hatch for a half-upgraded pair.
- **`sweep_stale_temps` leaked its loop variable to the caller** in all 11 copies (bash is dynamically scoped). Now `local`.
- **The no-op second `read` in the download content gate is gone**, along with the comment claiming it "confirms the file is more than a bare shebang" — its status was swallowed by `|| true` and nothing inspected it. Removed at all 19 sites across both repositories.
- **`utils/dig-all.sh` and `utils/reset-macOS-display-settings.sh` open-coded `$OSTYPE`** instead of calling `detect_os`, leaving `utils/` with two ways to decide the platform.
- **Documentation corrections.** `AGENTS.md` (both repositories) still taught the pre-fix loose shebang gate (`head -n 10 | grep -q "^#!/"`), the pre-fix `print_warning_box` off-by-one, and the stale `--color` claim, and its canonical-helper roster omitted `_sanitize_ansi`, `print_warning_box` and `detect_os` — so the rule that keeps the copies in sync did not formally cover the helper this work created. The roster is now a table with copy counts, deliberate variants, and an instruction to verify parity **across both repositories** (the previous check hashed only one repo's copies and so could not detect the divergence it missed). `utils/tests/README.md` no longer claims "no dependencies" for a suite that requires bash 5+, and its coverage table matches what the suite asserts.

### Changed

- **`utils/rsync-over-tunnel.sh` is now a generic directory-transfer tool, not an LXC-specific one.** `LXCPATH` → `TRANSFER_PATH`, `resolve_lxcpath` → `resolve_transfer_path`, and the header, runbook, and examples now describe transferring any directory tree. An idmapped LXC container rootfs remains the *motivating* example for `-aHS --numeric-ids` (it needs every one of those), but it is no longer the definition. LXC-specific lines dropped from 35 to 6, the survivors being that motivating-example note (in the header, the `--numeric-ids` comment, and the ACL warning box) plus one cross-reference to `lxc/setup-lxc.sh`, which uses the same GNU/BSD `stat` branch *shape* — note the format specifiers differ (`-c '%U'` / `-f '%Su'` here for the owner name, `-c "%u:%g"` / `-f "%u:%g"` there for numeric uid:gid).
- **BREAKING: the default rsyncd module name changed from `lxc` to `xfer`.** The module name is on the wire — it appears in the generated `rsyncd.conf` section header and in the `rsync://` URL. Both hosts must run this version, or pass `--module lxc` on both. A half-updated pair fails with `probe_daemon`'s existing "no rsync daemon answering … module 'xfer'" error rather than transferring to the wrong place.
- **The transfer's rsync flags are composed at runtime instead of hardcoded.** `--help` now advertises only the always-present flags (`-aHS --numeric-ids -W --partial-dir=.rsync-migrate`). `-A`/`-X` are added when **both** hosts support them (this build must be compiled with them and the target must speak protocol 30+); `--info=progress2` is added when **this** host's rsync is 3.1+ (protocol 31) — the target has no say in it, because this side formats the progress output. The exact composed command is printed immediately before it runs, so the operator can confirm at a glance which flags survived capability detection.

### Fixed

- **`utils/rsync-over-tunnel.sh` now runs on macOS.** Five platform bugs, each hidden behind the one before it: `stat -c '%U'` is GNU-only and BSD needs `-f '%Su'` (the reported crash); `date -Is` fails on BSD, which matches the `-I` format word exactly with no abbreviation; `/run` does not exist on macOS, so the throwaway config goes to `/var/run` (**not** `/var/tmp`, which `hier(7)` documents as surviving reboots and would defeat the dies-at-reboot guarantee); `reverse lookup = no` is not a valid openrsync config key and unknown keys are an unrecoverable error there; and `-A`/`-X`/`--info=` do not exist in openrsync at all.
- **ACL/xattr loss is now detected and consented to, not discovered mid-transfer.** A single `rsync --version` read yields implementation, compiled-in capabilities, and protocol number. `-A` and `-X` are tracked independently (a build can support one and not the other) and are added rather than negated, because openrsync has no `acls`/`xattrs` options for `--no-A`/`--no-X` to negate. The far end's protocol is read from its `@RSYNCD:` greeting, since local detection cannot see the remote and openrsync has no `--debug` to ask; `-A`/`-X` require protocol 30 on both sides. When anything is unavailable, a warning box names what is being dropped and *which side* is responsible, and requires explicit confirmation defaulting to **no**. Non-interactive runs abort.
- **`--info=progress2` is gated on protocol ≥ 31 and falls back to `--progress`.** `--info=FLAGS` shipped in rsync 3.1.0, which is exactly protocol 31, so the protocol number is an exact capability test rather than a version heuristic.
- **`sudo rsync` could run the wrong binary.** `sudo` resolves a bare command name against its own `secure_path`, not the caller's `PATH`, so on macOS `sudo rsync` could execute `/usr/bin/rsync` (openrsync) even with Homebrew's rsync first in `PATH` — the capability probe would pass and the daemon would still be the wrong binary. rsync is now resolved once to an absolute path and invoked by that path everywhere.
- **`use chroot` is claimed only where it can be honored.** macOS restricts `chroot(2)` to binaries holding `com.apple.private.vfs.chroot`, which only Apple's signed rsyncd carries, and an explicit `yes` makes `EPERM` fatal rather than a fallback. The daemon config now sets `use chroot = no` — with a visible warning — when running on macOS with a non-Apple rsync binary. The gate keys on the binary path, not the detected implementation, because a self-built openrsync would identify the same way and still be denied.
- **Fail fast on bash < 4.** `prompt_yes_no` uses `${var,,}`, a bash 4.0 expansion, and this script puts that prompt on the main path. macOS ships bash 3.2, where it is a runtime "bad substitution". The script now exits 69 pointing at `brew install bash` rather than dying at the prompt.
- **`print_warning_box` rendered every box with a ragged right edge (repo-wide).** `content_width` subtracted an extra 1, so a content row emitted 76 interior columns while the blank and border rows emitted 77. Fixed in all five copies (`utils/utils-misc.sh`, `system-setup/utils-sys.sh`, `kubernetes/utils-k8s.sh`, `lxc/utils-lxc.sh`, `llm/utils-llm.sh`).
- **Terminal-injection defense in the self-update diff preview (repo-wide, security).** `show_diff_box` renders remote file content through `less -R`, which deliberately passes ANSI through and does not filter cursor movement. Hostile content could therefore repaint the screen — most concretely, drawing a fake "no changes detected" line over the default-yes overwrite prompt that follows, turning one keypress into acceptance. A `_sanitize_ansi` helper now strips CSI sequences whose final byte is not `m`, plus BEL-terminated OSC, while keeping SGR colors. Applied to all 8 canonical copies (`utils/utils-misc.sh`, `system-setup/utils-sys.sh`, `kubernetes/utils-k8s.sh`, `lxc/utils-lxc.sh`, `llm/utils-llm.sh`, `github/gh_org_copy.sh`, `github/gh_org_delete_repos.sh`, `github/gh_org_delete_issues.sh`). Measured: a crafted file put 2 cursor-control sequences on the terminal before, 0 after.
- **Downloaded scripts now require a shebang on line 1 and reject CRLF (repo-wide, security).** The previous `head -n 10 | grep -q "^#!/"` accepted a shebang on *any* of the first ten lines, so an HTML error page quoting `#!/bin/sh` in a code snippet passed validation and was then `chmod +x`'d and `exec`'d. A CRLF-terminated shebang also passed, then failed at `exec` with `bash\r: not found` — after the download had already replaced the original on disk. Replaced at all 16 sites (curl and wget branches in each of the 8 copies). `github/gh_org_delete_repos.sh` had drifted to a negated variant of the check and is now back in line with the other seven.
- **The `--color` feature probe in `show_diff_box` carried a stale comment** claiming BSD/macOS `diff` does not support `--color`. macOS 26's `diff` does; only older releases do not. Corrected in all 8 copies — the claim had already caused one misdiagnosis.

## [2026-07-24]

### Added

- `utils/rsync-over-tunnel.sh` — one-way LXC lxcpath migration to another host over an SSH tunnel, using a throwaway root rsync daemon bound to loopback on the target. Preserves numeric ids / hardlinks / ACLs / xattrs / sparseness for idmapped container rootfs; leaves no persistent privilege or config behind (interactive sudo, no `NOPASSWD` drop-in). Standardized to Modular Standalone (sources `utils-misc.sh`, self-updates via `check_for_updates`). Subcommands: `target-tunnel`, `source-tunnel`, `source-transfer`. `--path` is required (no auto-detection). Option values are validated before use — port (decimal 1-65535, leading zeros rejected so bash cannot read `08` as octal), module name, and a control-character check on every value interpolated into the generated `rsyncd.conf`; the ssh target and the lxcpath are both guarded against option-injection, and a missing option value exits `64` like every other usage error. No cipher is forced (ssh negotiates unless `--cipher` is given). The exit handler reports whether the throwaway daemon config was actually removed instead of assuming it. Single-user target hosts only: the daemon module is unauthenticated, which the header and `docs/future-todos.md` both record.

## [2026-07-14]

### Added
- Ghostty terminfo push — `utils/push-ghostty-terminfo.sh` copies the local `xterm-ghostty` terminfo entry to a remote SSH host, defaulting to a **system-wide** install (`/usr/share/terminfo` via remote sudo) so every user including `root`/`su` resolves it, with a `--user` fallback to `~/.terminfo`. Complements Ghostty's per-user `ssh-terminfo` shell integration for cases where it is skipped (wrapper tools, non-interactive shells) or insufficient (root/other users). Multiplexes all SSH connections over one ControlMaster socket, so you authenticate to the host at most once — an interactive password/passphrase on a TTY, or key-based auth for non-interactive runs (cron, `ssh -T`); the system-wide default also prompts once for the remote sudo password. Idempotent, self-updating, single-host.
- Ghostty configuration reference — `configs/ghostty.md` documents the recommended `shell-integration-features = ssh-terminfo,ssh-env` settings and when to fall back to the push script.
