## [2026-10-10]

### Changed

- **The `lxc/` and `llm/` scripts reap stale self-update temps, and the `lxc/` suite tests the stop, restore and SSH paths by behaviour.** The eleven `lxc/` launchers with a `main`, `llm/ollama-remote.sh` and `llm/ollama-screen.sh` now call `sweep_stale_temps '~*.tmp.??????'` first in `main()`, and `lxc/setup-lxc.sh` calls it at file scope before `check_for_updates`, as AGENTS.md's Minimal Script Template asks, so a `~<script>.tmp.XXXXXX` left by a killed self-update is deleted on the next run instead of only when the updater runs. `lxc/tests/test-protect-lxc.sh` refuses to run as root (exit 64), since `lxc_resolve_path` would then name the real `/var/lib/lxc`; its `_lxc_main` harness stubs the sweep, takes per-case stubs through `EXTRA_STUBS` and names the stubbed archive's top-level entry through `TAR_TOP`. The source-text pins on the `lxc-ls` capture in `stop-lxc.sh` and `restart-lxc.sh` give way to a behavioural `stop-lxc.sh` case that stubs `/usr/bin/lxc-ls` with a function of that name: two listed names each reach `lxc-stop`, an empty list reports no running containers, and a failing `lxc-ls` exits 1; `restart-lxc.sh`'s capture is no longer pinned. New cases cover `create-lxc.sh` warning and going on to `lxc-create` when `/etc/os-release` names no distribution or release, and `restore-lxc.sh` refusing `..` as the archive's container name (exit 65) and `a/b` as the new name (exit 64). `lxc/README.md` states the accepted container-name pattern and which scripts refuse other names.
- **Lightweight scripts run under `set -euo pipefail`, the library-check pin's reach is stated, and every per-line shellcheck disable carries its reason.** AGENTS.md §4 Lightweight Scripts asks for `set -euo pipefail` at the top like every script instead of calling it optional. `utils/monitor-battery.sh`, `utils/disable-kvm-module.sh` and the section's example now carry it, with `|| true` where a failure must not end the run: the `grep` that finds no percentage line on a host without `battery_BAT1`, and the two vendor-module `modprobe -r` calls, which fail only when the kernel lacks the module or cannot unload it (removing a module that is not loaded succeeds). The last `modprobe -r kvm` still sets the exit status. Without those, the loop would end at its first unmatched `grep` and the KVM script at its first failed removal. §3 says the four-line library check is pinned only in scripts whose `source` line has the template's spelling. The six `# shellcheck disable=` directives whose reason sat on the lines above carry it after the directive: two SC2029 in `utils/push-ghostty-terminfo.sh`, SC2086 in `initialize-cluster.sh`, and three SC2016 in `tests/test-self-update.sh`.
- **One `detect_download_cmd` body in all eight helper copies, and `download_script`'s comments state the code as it is.** `kubernetes/utils-k8s.sh` and the three `github/gh_org_*.sh` standalones now carry the libraries' `detect_download_cmd`. The k8s copy gains the macOS `brew install curl` line of its "UPDATES NOT AVAILABLE" box. The standalones show that box instead of their two `print_warning`/`print_info` lines, so they carry `print_warning_box` too. The AGENTS.md snippet is the same body. `tests/test-self-update.sh` pins `detect_download_cmd` and `print_warning_box` to one digest across the eight copies, as it already pinned `download_script`, and AGENTS.md §Helper Library Duplication lists both at eight copies. `download_script`'s comment on its 200 branch states the rule, that only line 1 may carry the shebang, instead of comparing it with the grep it replaced, and every copy carries the libraries' three-line header comment.

### Fixed

- **The `github/` scripts find milestones on every page, keep a bulk run going after a failure, exit 64 on a usage error and show `gh`'s own errors, and a new suite pins it.** `gh_org_copy.sh` looks a destination milestone up through one helper, `dest_milestone_number_by_title`, which reads every page (`--paginate`) and hands the title to `jq` as data. The old lookup could never return a number (`gh`'s `--jq` takes no variables, and its `--raw-field` turned the request into a POST), so every copied issue lost its milestone; and the existence check in `copy_labels_and_milestones` read only the first 100 milestones and broke on a title containing `"`, so such a milestone was created again on every run. `create_issue_in_dest` accepts the new issue's number only when the POST returned one: a failed POST is reported on stderr with the response and skipped, instead of being commented on and closed as `/issues/null`, and its "Issue already exists" message goes to stderr, outside the number its callers capture. Archived PR comments, review comments and reviews by a deleted account, and the archived PR's own author, are attributed to `@unknown` instead of `@null`, and the review-comment filter is parenthesised so plain `jq` parses it the way `gh`'s gojq does. `gh_org_delete_issues.sh` counts a failed close and goes on to the remaining issues and repositories, where it used to exit 1 before the Summary; counts a repository whose issues cannot be listed as skipped only, no longer also as processed; and sends the owner and repository name of the `--really-delete` node-id lookup as strings (`-f`), so a repository named `2024` or `true` is deleted instead of closed. An unknown option in either delete script, and `gh_org_delete_repos.sh`'s missing-target and `--all`-with-names errors, exit 64 (`EX_USAGE`) instead of 0, while `--help` exits 0; `gh repo delete`, `gh repo view` and `gh issue close` show their own error message beside the script's. `copy_labels_and_milestones` declares its loop variables and `args` array `local`, and the duration `printf` quotes its arguments. `github/tests/test-gh-org.sh` covers each behaviour with `gh` shimmed, so `./test-all.sh` runs six suites; `github/tests/README.md` documents it, and the READMEs of the other suites count the assertion trio's five copies.
- **`backup-lxc.sh` and `restore-lxc.sh` answer `--help` and argument errors on a host without 7z.** Both checked for their tools before parsing their arguments, so `--help`, an invalid container name or a missing container or archive ended in "7z is required" with exit 69. `check_required_tools` now runs after the argument, name and input checks: in `backup-lxc.sh` before the backup directory is created, in `restore-lxc.sh` before the archive is read.
- **`migrate-to-systemd-networkd.sh` keeps an IPv6 prefix length.** `generate_network_file` read an `inet6 static` stanza's `netmask` and never used it, so `address 2001:db8::10` with `netmask 64` became `Address=2001:db8::10` with no prefix length; it now writes `Address=<address>/<netmask>` when the address carries no `/` (interfaces(5) gives the inet6 netmask as a number of bits). `verify_network_connectivity` counts and reports `routable` interfaces only, dropping comparisons with `configured`, a SETUP state that never appears in the OPERATIONAL column it reads; and `get_interface_list` tolerates an empty `ifquery` list explicitly, so a bare call no longer aborts on a host whose only `auto` interface is `lo`.
- **A network-migration rollback puts `/etc/resolv.conf` back the way it found it.** The rollback after a failed connectivity check, and the `ln -s` failure branch, restored the newest `resolv.conf.backup.*.bak` they could find: a symlink managed by resolvconf came back as a frozen copy of its target, and when this run had made no backup, an older one from an earlier run was restored. `configure_resolv_conf` now records a symlink's own target and the backup this run made, and `restore_resolv_conf` recreates the symlink or copies that backup, nothing else.
- **`system-configuration.sh` keeps the "managed by system-setup.sh" header above the prompt block it inserts.** With exactly one `PS1=` line in `/etc/bash.bashrc`, the block was written over the header `add_change_header` had just put in the temporary file; it is now appended after it, and the temporary file is registered for the EXIT trap.
- **`install-update-minikube.sh` holds its install command in an array.** It ran a space-separated string through an unquoted expansion; `"${install_cmd[@]}"` passes `apt install` or `<manager> install -y` and the package path as separate arguments.
- **The lint gate's `.shellcheckrc` and file-wide checks fail closed, and the execution-guard pin catches `[ … ] &&`.** `tests/test-shellcheck.sh` checks `.shellcheckrc` against an allowlist: every line is blank, a comment, `external-sources=true`, or `source-path=` with one unquoted path. Its deny-list regex let `extended-analysis=false`, a quoted `source-path` value followed by `disable=`, and a tab before a `#` carry a repo-wide key past it. A `# shellcheck` directive before a script's first command may carry only the `source`, `source-path`, `external-sources` and `enable` keys, where only `disable=` was refused there. A `grep` or `awk` that cannot run is a FAIL line instead of reading as "nothing found", and the nested-rc search skips `.claude/worktrees/` only, no longer all of `.claude/`. `tests/test-self-update.sh` pins `BASH_SOURCE … ] &&`, so a distributed script ending in `[ "${BASH_SOURCE[0]}" = "$0" ] && main "$@"` fails the suite as the `[[ … ]] &&` form already did.

### Security

- **`gh_org_copy.sh` works in a directory only the operator owns.** The default `WORKDIR` was the predictable `/tmp/org-copy-<src>-to-<dst>`, and `mkdir -p` accepted one that another local user had created first, who could then plant or symlink the PR-conversation JSON files written there: the operator's own files overwritten, or planted content posted under the operator's token. `prepare_workdir` now creates a fresh `mktemp -d` directory under `$TMPDIR` (else `/tmp`) by default. A `WORKDIR` the caller names must be the caller's own, and a symlink is refused even when it points to a directory the caller owns; either refusal exits 77 (`EX_NOPERM`). The configuration screen shows "a new directory under …" until the directory exists.
- **`config-lxc-ssh.sh` no longer follows a symlink inside a container.** It runs as root and writes into the container's rootfs, which the container's root and the target user control, so a link at the user's home, `.ssh` or `authorized_keys` (e.g. `authorized_keys -> /root/.ssh/authorized_keys`) sent the appended key and the `chmod 600` to a host file, and left a copy of that file in `.ssh` owned by the container's user. `configure_container_ssh` now resolves the home with `realpath -e` and requires it inside the resolved rootfs, refuses a symlinked `.ssh` or `authorized_keys`, and skips such a container with a warning that names the path. `lxc/tests/test-protect-lxc.sh` covers a plain home and each of the three links.
- **BREAKING: `utils/rsync-two-way.sh` no longer deletes remote-only files, and refuses an `rsync://` spec.** Both passes ran rsync with `--delete`, so Pass 1 (LOCAL to REMOTE) deleted every file that existed only on the remote before Pass 2 could pull it, and the run still reported success. Neither pass deletes now: a file that exists on one side only is copied to the other, and `--update` keeps the newer copy of a file that exists on both ([rsync(1)](https://download.samba.org/pub/rsync/rsync.1)). A deletion must now be made on both sides by hand. `validate_sync_args` also refuses an `rsync://` daemon spec with exit 1, because its format check read the scheme as the host and never checked the real one; `--help`, the header and `utils/README.md` name every refusal and the `./` escape. `rsync-over-tunnel.sh --help` answers before the stale-temp sweep and the update check. `utils/tests/test-rsync-two-way.sh` points `HOME` into its sandbox before it sources the script, covers the missing-directory error, pins that no `--delete` reaches rsync, and asserts the guard's own message in its child-process run; `test-rsync-over-tunnel.sh` shims `ssh` for the `cmd_source_tunnel` guard, so it passes on a host with no ssh client, and pins `main`'s call to `validate_extra` for `source-transfer` as well.

## [2026-10-01]

### Added

- **Lint gate: a repo-root `.shellcheckrc` and `tests/test-shellcheck.sh`.** The rc sets `external-sources=true` and `source-path=SCRIPTDIR`, so a bare `shellcheck <file>` follows each script's `source` relative to its own directory from any working directory; the suite lints every tracked `*.sh` at the default severity and exits 1 naming each file with a finding, rejects a `disable=` or `shell=` directive in the rc (also one that follows another key on the same line or is glued to a quoted value), a `# shellcheck disable=` placed before a script's first command (shellcheck applies that one to the whole file) or a nested rc that would shadow it, and unsets `SHELLCHECK_OPTS` so a personal default cannot weaken it. `AGENTS.md` §Linting names it the gate and drops the allowance for pre-existing findings, since every tracked script is now at 0.
- **`test-all.sh` at the repository root runs every test suite.** It lists each tracked `test-*.sh` below the root from the git index, so a new suite is picked up once it is committed, runs them in turn, and exits 1 naming each suite that failed — the lint gate included. `AGENTS.md` §Running the Scripts makes it the check before every commit that changes a script.
- **The generated `rsyncd.conf`'s key set is a test gate.** `utils/tests/test-rsync-over-tunnel.sh` now requires the keys `build_daemon_config` emits (16 with `use chroot = no`, 15 with `yes`) to equal `OPENRSYNC_VERIFIED_KEYS`, the list checked against openrsync's `rsync_daemon_params[]` on 2026-08-06, so a new directive fails the suite until it has been checked against that table. openrsync treats an unknown key as an unrecoverable error, so one unchecked key would kill step 1 on every macOS target running Apple's `/usr/bin/rsync`; until now only a code comment asked for the check.
- **A missing directory library is named instead of crashing the script.** The 24 `lxc/`, `llm/` and `utils/` scripts that source their directory's library — `utils-lxc.sh`, `utils-llm.sh` or `utils-misc.sh`, the three `_download-*-scripts.sh` updaters included — now check that it exists first. A script copied or curled on its own used to die under `set -e` with bash's raw `No such file or directory` from its `source` line; it now exits 69 (`EX_UNAVAILABLE`) with one line on stderr naming the file, the directory it looked in, and the updater to fetch beside it — `utils-misc.sh not found in /path: download it and _download-utils-scripts.sh there, then run ./_download-utils-scripts.sh`. The check runs before the library loads, so it prints with a raw `printf`, not `print_error`. AGENTS.md §3 states the rule, both script templates carry the block, and §3 corrects its old claim that `_download-*-scripts.sh` downloads the library: `get_script_list()` excludes the library, and the updater sources it too, so the updater alone cannot bootstrap a directory. `tests/test-self-update.sh` runs one script per suite with and without its library and pins the block verbatim in all 24; `lxc/README.md`, `llm/README.md` and `utils/README.md` document the exit.

### Fixed

- **`utils/rsync-over-tunnel.sh` now runs on macOS.** Five platform bugs, each hidden behind the one before it: `stat -c '%U'` is GNU-only and BSD needs `-f '%Su'` (the reported crash); `date -Is` fails on BSD, which matches the `-I` format word exactly with no abbreviation; `/run` does not exist on macOS, so the throwaway config goes to `/var/run` (**not** `/var/tmp`, which `hier(7)` documents as surviving reboots and would defeat the dies-at-reboot guarantee); `reverse lookup = no` is not a valid openrsync config key and unknown keys are an unrecoverable error there; and `-A`/`-X`/`--info=` do not exist in openrsync at all.
- **ACL/xattr loss is now detected and consented to, not discovered mid-transfer.** A single `rsync --version` read yields implementation, compiled-in capabilities, and protocol number. `-A` and `-X` are tracked independently (a build can support one and not the other) and are added rather than negated, because openrsync has no `acls`/`xattrs` options for `--no-A`/`--no-X` to negate. - **`sudo rsync` could run the wrong binary.** `sudo` resolves a bare command name against its own `secure_path`, not the caller's `PATH`, so on macOS `sudo rsync` could execute `/usr/bin/rsync` (openrsync) even with Homebrew's rsync first in `PATH` — the capability probe would pass and the daemon would still be the wrong binary. rsync is now resolved once to an absolute path and invoked by that path everywhere.

The daemon config now sets `use chroot = no` — with a visible warning — when running on macOS with a non-Apple rsync binary. The gate keys on the binary path, not the detected implementation, because a self-built openrsync would identify the same way and still be denied.
- **Fail fast on bash < 4.** `prompt_yes_no` uses `${var,,}`, a bash 4.0 expansion, and this script puts that prompt on the main path. macOS ships bash 3.2, where it is a runtime "bad substitution". The script now exits 69 pointing at `brew install bash` rather than dying at the prompt.
- **`print_warning_box` rendered every box with a ragged right edge (repo-wide).** `content_width` subtracted an extra 1, so a content row emitted 76 interior columns while the blank and border rows emitted 77. Fixed in all five copies (`utils/utils-misc.sh`, `system-setup/utils-sys.sh`, `kubernetes/utils-k8s.sh`, `lxc/utils-lxc.sh`, `llm/utils-llm.sh`).
- **Terminal-injection defense in the self-update diff preview (repo-wide, security).** `show_diff_box` renders remote file content through `less -R`, which deliberately passes ANSI through and does not filter cursor movement. Hostile content could therefore repaint the screen — most concretely, drawing a fake "no changes detected" line over the default-yes overwrite prompt that follows, turning one keypress into acceptance. A `_sanitize_ansi` helper now strips CSI sequences whose final byte is not `m`, plus BEL-terminated OSC, while keeping SGR colors. Applied to all 8 canonical copies (`utils/utils-misc.sh`, `system-setup/utils-sys.sh`, `kubernetes/utils-k8s.sh`, `lxc/utils-lxc.sh`, `llm/utils-llm.sh`, `github/gh_org_copy.sh`, `github/gh_org_delete_repos.sh`, `github/gh_org_delete_issues.sh`). Measured: a crafted file put 2 cursor-control sequences on the terminal before, 0 after.
- **Downloaded scripts now require a shebang on line 1 and reject CRLF (repo-wide, security).** The previous `head -n 10 | grep -q "^#!/"` accepted a shebang on *any* of the first ten lines, so an HTML error page quoting `#!/bin/sh` in a code snippet passed validation and was then `chmod +x`'d and `exec`'d. A CRLF-terminated shebang also passed, then failed at `exec` with `bash\r: not found` — after the download had already replaced the original on disk.
